Architecture

Request pipeline for every advisory. The same flow is implemented in src/ — small, auditable, and cheap to run.

1 · Auth→ 2 · Classify→ 3 · Retrieve→ 4 · Weather→ 5 · Safety→ 6 · Persist

1 · Auth

PBKDF2-SHA256 (120k iterations) password hashing, random 256-bit session tokens with 30-day expiry. Accepts email or username. src/auth.ts

2 · Classify

Keyword classifier over 23 topics with English + Hindi terms; Devanagari detection for language. src/classify.ts

3 · Retrieve

TF-IDF with Unicode-safe tokenization over 295 records; cosine similarity, optional crop boost. Hindi retrieval uses the same tokenizer — no ASCII assumptions. src/retrieval.ts

4 · Weather

Mock provider by default (clearly labeled). Drop-in Open-Meteo interface enabled via WEATHER_PROVIDER=open-meteo. src/weather.ts

5 · Safety

Exact-dosage requests get guidance instead of a dose; low-confidence queries get clarifying questions; every answer carries a disclaimer and source IDs. src/safety.ts

6 · Persist

Advisories saved per user in a JSON store (data/app.db.json, gitignored). History API powers the advisor's timeline. src/store.ts

Where the SLM fits

This service runs in retrieval-grounded mode over the curated knowledge base — the honest, low-cost baseline. The companion ML pipeline fine-tunes a small instruction model (Qwen2.5-1.5B-Instruct, QLoRA) on the same data; when an adapter is trained, it slots in as the answer composer between steps 3 and 5, with retrieval and safety unchanged.

Knowledge base→ Retrieval (now)→ Fine-tuned SLM (next)→ Safety gate
